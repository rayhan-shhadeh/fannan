## Naming Conventions

| Aspect | Convention | Example | Rationale |
|--------|-----------|---------|-----------|
| Table names | snake_case, plural | `users`, `orders`, `order_items` | SQL standard; lowercase for consistency |
| Column names | snake_case | `created_at`, `user_id`, `base_price` | Consistent with table naming |
| Primary keys | `id` (UUID) | `id UUID PRIMARY KEY` | Globally unique; no reliance on sequence |
| Foreign keys | `{entity}_id` | `user_id`, `product_id`, `order_id` | Clear reference to parent entity |
| Join tables | `{entity_a}_{entity_b}` | `product_categories`, `collection_items` | Composite PK on both FKs |
| Boolean flags | Prefix `is_` or `allow_` | `is_active`, `allow_offers`, `is_archived` | Clarity on semantic meaning |
| Timestamp columns | `created_at`, `updated_at` | Consistently named | Standard ORM convention |
| Status/state columns | `{entity}_status` | `order_status`, `artist_verification_status` | Reduce ambiguity |
| Soft delete markers | `deleted_at` (not `is_deleted`) | `deleted_at TIMESTAMPTZ NULL` | Allows tracking when deletion occurred |
| Index names | `idx_{table}_{columns}` | `idx_orders_buyer_id`, `idx_artworks_artist_id` | Clarity on index purpose |
| Unique constraint names | `uniq_{table}_{columns}` | `uniq_users_email`, `uniq_artist_profiles_user_id` | Descriptive naming for debugging |
| Foreign key names | `fk_{table}_{column}` | `fk_orders_buyer_id`, `fk_order_items_order_id` | Clarity on constraint |

## PostgreSQL Data Types & Guidelines

### Recommended Type Choices

| Data | Type | Usage | Example |
|------|------|-------|---------|
| Unique Identifier | `UUID` | All primary keys, most foreign keys | `id UUID PRIMARY KEY DEFAULT gen_random_uuid()` |
| Money / Currency | `NUMERIC(15, 2)` | All monetary values (not FLOAT) | `base_price NUMERIC(15, 2) NOT NULL` |
| Text (short) | `VARCHAR(length)` | Emails, names, SKUs | `email VARCHAR(254) NOT NULL` |
| Text (long) | `TEXT` | Descriptions, biographies, JSON | `description TEXT`, `metadata JSONB` |
| JSON / Flexible | `JSONB` | Flexible structures, metadata, non-critical data | `metadata JSONB DEFAULT '{}'::JSONB` |
| Timestamp | `TIMESTAMPTZ` | All timestamps (timezone-aware) | `created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP` |
| Boolean | `BOOLEAN` | Flags, toggles | `is_active BOOLEAN NOT NULL DEFAULT true` |
| Status / Enum | `{ENUM_TYPE}` | Status machines | `status order_status_enum NOT NULL` |
| Large Binary | NOT USED in DB | Media binaries | Store in S3; DB holds only metadata/URL |
| Serial / Increment | `BIGINT` | NOT recommended for MVP | Use UUID instead |

### Type Rationale

- **UUID vs BIGINT:** UUID provides global uniqueness without coordination; scales horizontally
- **NUMERIC(15,2) vs FLOAT:** NUMERIC prevents rounding errors in financial calculations (critical)
- **TIMESTAMPTZ vs TIMESTAMP:** TIMESTAMPTZ captures timezone info; always UTC at DB boundary
- **JSONB vs TEXT:** JSONB allows querying and indexing flexible fields; TEXT requires full-text search
- **ENUM vs VARCHAR:** ENUM enforces valid values at DB level; reduces bugs and storage

## Monetary Value Handling

All monetary values use `NUMERIC(15, 2)` with specific semantic meanings. This ensures precision and prevents rounding errors in financial transactions.

### Price Types & Semantics

| Price Type | Table | Column | Meaning | Example |
|-----------|-------|--------|---------|---------|
| **Base Price** | `artworks` | `base_price` | Artist's standard selling price for product | 150.00 (USD) |
| **Offer Price** | `offers` | `proposed_price` | Customer's initial or counter offer | 120.00 (USD) |
| **Agreed Price** | `negotiated_agreements` | `agreed_price` | Final negotiated price accepted by artist | 130.00 (USD) |
| **Order Unit Price** | `order_items` | `unit_price` | Price per item at order creation time (snapshot) | 130.00 (negotiated) or 150.00 (base) |
| **Order Total** | `orders` | `total_amount` | Sum of all items + shipping + tax (if future) | SUM(order_items) + shipping_cost |
| **Payment Amount** | `payments` | `amount` | Amount paid in transaction (may differ from order total if partial) | 130.00 |
| **Shipping Cost** | `shipments` | `cost` | Carrier's shipping fee | 15.00 |
| **Discount Amount** | `orders` | `discount_amount` (future) | Coupon/promotional discount | 10.00 |

### Currency Handling

- Store **primary currency** in a `currency` column (VARCHAR, typically "USD" for MVP)
- All monetary columns use **single currency** within an order (multi-currency future phase)
- Example: `artworks.currency = 'USD'`, `orders.currency = 'USD'`

### Validation Rules

```sql
-- Check constraint: all monetary values must be >= 0
ALTER TABLE artworks ADD CONSTRAINT chk_base_price_positive CHECK (base_price > 0);
ALTER TABLE offers ADD CONSTRAINT chk_proposed_price_positive CHECK (proposed_price > 0);
ALTER TABLE order_items ADD CONSTRAINT chk_unit_price_valid CHECK (unit_price > 0 AND quantity > 0);
ALTER TABLE payments ADD CONSTRAINT chk_payment_amount_positive CHECK (amount > 0);
ALTER TABLE shipments ADD CONSTRAINT chk_shipping_cost_nonnegative CHECK (cost >= 0);
```

### 1. USERS Table (Identity & Access Bounded Context)

**Purpose:** Core user account and authentication for all platform users (customers and artists).

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  
  -- Authentication & Identity
  email VARCHAR(254) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  
  -- User Profile
  display_name VARCHAR(255) NOT NULL,
  bio TEXT,
  profile_picture_url VARCHAR(2048),
  phone VARCHAR(20),
  locale VARCHAR(10) DEFAULT 'en' NOT NULL,
  
  -- Status & Roles
  status user_status_enum DEFAULT 'active' NOT NULL,
  
  -- Metadata (extensible)
  metadata JSONB DEFAULT '{}'::JSONB,
  
  -- Timestamps
  created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted_at TIMESTAMPTZ NULL,
  
  -- Constraints
  CONSTRAINT chk_email_format CHECK (email ~ '^[A-Za-z0-9._%+\-]+@[A-Za-z0-9.\-]+\.[A-Z|a-z]{2,}$'),
  CONSTRAINT chk_display_name_not_empty CHECK (display_name <> '')
);

CREATE INDEX idx_users_email ON users (email) WHERE deleted_at IS NULL;
CREATE INDEX idx_users_status ON users (status);
CREATE INDEX idx_users_created_at ON users (created_at DESC);
```

**Columns:**
- `id`: UUID primary key
- `email`: Unique email; soft-delete via deleted_at allows re-registration
- `password_hash`: Bcrypt/Argon2 hash; never store plain password
- `display_name`: User's public name (for marketplace)
- `bio`: Optional biography/profile text
- `profile_picture_url`: S3 reference (URL stored, not binary)
- `phone`: Optional; used for SMS notifications (future)
- `locale`: Language/locale preference (e.g., "en", "ar")
- `status`: User account status (active, suspended, deleted)
- `metadata`: JSON for extensible fields (preferences, settings)
- `created_at`, `updated_at`: Standard timestamps
- `deleted_at`: Soft-delete marker (NULL = active)

**Business Rules:**
- Email is unique and required
- Password is salted hash (never plain text)
- User can be both Customer and Artist (no separate roles in users table)
- Artist capabilities gated by artist_profile.verification_status

### 2. ARTIST_PROFILES Table (Artist Management Bounded Context)

**Purpose:** Artist-specific profile, public storefront, and verification state. Owned by User.

```sql
CREATE TABLE artist_profiles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  
  -- User Reference (1:1)
  user_id UUID NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL,
  CONSTRAINT uniq_artist_profiles_user_id UNIQUE (user_id),
  
  -- Artist Public Profile
  display_name VARCHAR(255) NOT NULL,
  public_bio TEXT,
  location VARCHAR(255),
  
  -- Marketplace Settings
  allow_offers BOOLEAN DEFAULT false NOT NULL,
  
  -- Verification Status (state machine)
  verification_status artist_verification_status_enum DEFAULT 'not_applied' NOT NULL,
  verification_submitted_at TIMESTAMPTZ,
  verification_decision_at TIMESTAMPTZ,
  verification_notes TEXT,
  
  -- Payout Information (reference to external vault, not stored here)
  payout_details_reference VARCHAR(255),
  
  -- Social Links (JSON)
  social_links JSONB DEFAULT '{}'::JSONB,
  
  -- Shipping Policies (JSON, future detail)
  shipping_policies JSONB DEFAULT '{}'::JSONB,
  
  -- Timestamps
  created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted_at TIMESTAMPTZ NULL,
  
  CONSTRAINT chk_artist_display_name_not_empty CHECK (display_name <> '')
);

CREATE INDEX idx_artist_profiles_user_id ON artist_profiles (user_id);
CREATE INDEX idx_artist_profiles_verification_status ON artist_profiles (verification_status);
CREATE INDEX idx_artist_profiles_created_at ON artist_profiles (created_at DESC);
```

**Columns:**
- `user_id`: FK to users (1:1 relationship, unique constraint)
- `display_name`: Artist's storefront name
- `public_bio`: Public biography (Markdown-safe, HTML sanitized in app)
- `allow_offers`: Boolean flag; per-artwork override in artworks table
- `verification_status`: State machine: not_applied → pending → approved/rejected → suspended
- `verification_submitted_at`, `verification_decision_at`: Audit timestamps
- `payout_details_reference`: Opaque reference to payment processor vault (never store raw account details)
- `social_links`: JSON { "instagram": "...", "website": "..." }

**Business Rules:**
- Cannot publish artworks until `verification_status = 'approved'`
- Artist can toggle `allow_offers` globally; individual artworks can override
- Verification state transitions logged in audit_log for compliance

### 4. ARTWORKS (Products/Listings) Table (Catalog & Product Bounded Context)

**Purpose:** Core product/artwork entity. Can be physical/digital, unique/quantity.

```sql
CREATE TABLE artworks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  
  -- Ownership & Creator
  artist_id UUID NOT NULL,
  FOREIGN KEY (artist_id) REFERENCES users(id) ON DELETE SET NULL,
  
  -- Basic Information
  title VARCHAR(255) NOT NULL,
  description TEXT,
  
  -- Type & Classification
  type artwork_type_enum NOT NULL, -- physical | digital
  supply_type supply_type_enum NOT NULL, -- unique | quantity
  
  -- Pricing
  base_price NUMERIC(15, 2) NOT NULL,
  currency VARCHAR(3) DEFAULT 'USD' NOT NULL,
  
  -- Negotiation (optional)
  allow_offers BOOLEAN DEFAULT false NOT NULL, -- override artist level default
  private_minimum_price NUMERIC(15, 2), -- encrypted column in production; never shown to customers
  
  -- Product Metadata
  sku VARCHAR(128),
  year INTEGER,
  dimensions TEXT, -- JSON { "height": ..., "width": ..., "depth": ..., "unit": "cm" }
  materials TEXT, -- JSON array ["oil", "canvas"]
  story TEXT, -- Artwork story/artist notes
  
  -- Status
  status artwork_status_enum DEFAULT 'draft' NOT NULL,
  published_at TIMESTAMPTZ,
  
  -- Metadata
  metadata JSONB DEFAULT '{}'::JSONB,
  
  -- Timestamps
  created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted_at TIMESTAMPTZ NULL,
  
  -- Constraints
  CONSTRAINT chk_artwork_title_not_empty CHECK (title <> ''),
  CONSTRAINT chk_artwork_base_price_positive CHECK (base_price > 0),
  CONSTRAINT chk_artwork_private_min_positive CHECK (private_minimum_price IS NULL OR private_minimum_price > 0),
  CONSTRAINT chk_artwork_type_valid CHECK (type IN ('physical', 'digital')),
  CONSTRAINT chk_supply_type_valid CHECK (supply_type IN ('unique', 'quantity'))
);

CREATE INDEX idx_artworks_artist_id ON artworks (artist_id);
CREATE INDEX idx_artworks_status ON artworks (status) WHERE deleted_at IS NULL;
CREATE INDEX idx_artworks_type ON artworks (type);
CREATE INDEX idx_artworks_created_at ON artworks (created_at DESC);
CREATE INDEX idx_artworks_published ON artworks (published_at DESC) WHERE status = 'published' AND deleted_at IS NULL;
```

**Columns:**
- `artist_id`: FK to users (creator/seller)
- `title`, `description`: Text fields
- `type`: physical | digital (physical requires shipping, digital doesn't)
- `supply_type`: unique (only 1 copy) | quantity (reproducible, stock-managed)
- `base_price`: Standard selling price
- `currency`: ISO 4217 code (USD for MVP)
- `allow_offers`: Enable negotiation on this specific artwork
- `private_minimum_price`: Artist's private floor (encrypted; never queried in customer views)
- `sku`: Optional stock-keeping unit
- `status`: draft → published → available | hidden | suspended | archived
- `published_at`: Timestamp of publication
- `metadata`: JSONB for extended attributes (certificate info, authentication, etc.)

**Business Rules:**
- Cannot be published if `artist_id` → artist_profile.verification_status ≠ 'approved'
- If `supply_type = 'unique'`, inventory.quantity_total must = 1
- Price changes do not retroactively affect existing orders
- Deleted artworks are soft-deleted; orders/media preserved

### 5. PRODUCT_MEDIA Table (Media Bounded Context)

**Purpose:** Metadata for artwork images, videos, downloads. Binaries stored in S3; DB holds references.

```sql
CREATE TABLE product_media (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  
  -- Product Reference
  product_id UUID NOT NULL,
  FOREIGN KEY (product_id) REFERENCES artworks(id) ON DELETE CASCADE,
  
  -- Media Metadata
  media_type media_type_enum NOT NULL, -- image | video | download | preview
  
  -- S3 Reference (stored as URL, not binary)
  s3_key VARCHAR(2048) NOT NULL, -- full S3 object key
  s3_url VARCHAR(2048) NOT NULL, -- public/signed URL
  mime_type VARCHAR(128) NOT NULL, -- image/jpeg, application/pdf
  
  -- Image Metadata (if image)
  width INTEGER, -- pixels
  height INTEGER,
  
  -- File Metadata
  file_size_bytes BIGINT, -- storage tracking
  
  -- Display Metadata
  alt_text TEXT, -- accessibility
  order_index INTEGER DEFAULT 0, -- display order in gallery
  
  -- Timestamps
  created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted_at TIMESTAMPTZ NULL,
  
  CONSTRAINT chk_s3_key_not_empty CHECK (s3_key <> ''),
  CONSTRAINT chk_mime_type_valid CHECK (mime_type <> '')
);

CREATE INDEX idx_product_media_product_id ON product_media (product_id);
CREATE INDEX idx_product_media_order_index ON product_media (product_id, order_index);
```

**Columns:**
- `product_id`: FK to artworks
- `media_type`: image | video | download | preview
- `s3_key`: Full S3 path (e.g., `artworks/user123/product456/media001.jpg`)
- `s3_url`: Publicly accessible or signed URL
- `mime_type`: MIME type for content negotiation
- `width`, `height`: For images; for layout optimization
- `file_size_bytes`: Track storage usage
- `alt_text`: Accessibility text (alt tags for screen readers)
- `order_index`: Sequence for gallery display

**Business Rules:**
- Binaries never stored in PostgreSQL
- URLs may be signed (time-limited access) for private assets
- S3 deletion coordinated with application (not cascading from DB)

### 6. DIGITAL_ASSETS Table (for Digital Product Entitlements)

**Purpose:** Metadata for digital products delivered on purchase (access control, entitlements).

CREATE TABLE digital_assets (

## Prisma Schema Mapping Strategy

### General Mapping Rules

1. **Model Names:** Use PascalCase in Prisma (e.g., `model User`, `model Artwork`)
2. **Field Names:** Use camelCase in Prisma (e.g., `displayName`, `basePrice`)
3. **Primary Keys:** All models use `id String @id @default(cuid())`  OR  `id String @id @default(uuid())`
4. **Foreign Keys:** Relation fields + `@relation` attributes
5. **Unique Constraints:** `@unique` or `@@unique([...])` for composite
6. **Enums:** Prisma `enum` type declarations
7. **Timestamps:** `DateTime @db.Timestamptz`  with `@default(now())` and `@updatedAt`
8. **Money:** `Decimal @db.Numeric(15, 2)`
9. **Soft Deletes:** `deletedAt DateTime? @db.Timestamptz`

### Relations and Cascade Behavior

In Prisma, cascade deletion is specified via `onDelete`:

```prisma
// CASCADE
FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
// Maps to:
user User @relation(fields: [userId], references: [id], onDelete: Cascade)

// SET NULL
FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
// Maps to:
user User? @relation(fields: [userId], references: [id], onDelete: SetNull)

// RESTRICT
FOREIGN KEY (product_id) REFERENCES artworks(id) ON DELETE RESTRICT
// Maps to:
product Artwork @relation(fields: [productId], references: [id], onDelete: Restrict)
```
