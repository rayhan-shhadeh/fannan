## Lifecycle Concepts

### Deletion Types

**Hard Delete:** Complete removal of record from database. Recommended only for data without business/legal significance (e.g., draft cart items, temporary session data).

**Soft Delete:** Record marked with `deleted_at` timestamp but remains queryable. Preserves referential integrity for historical records (e.g., orders, audit logs).

**Archive:** Record moved to inert state (e.g., `status = 'archived'`) but remains queryable. Used when status/state transitions are explicit business operations.

**Status Transition:** Record state changes via enum (e.g., `artwork.status: draft → published`). Used for operational state management.

**Immutable Record:** Record written once and never modified (append-only pattern). Used for audit logs, financial records, and compliance-sensitive data.

### Key Principles

1. **Preserve History:** Soft-delete business records so they remain findable for reconciliation, audits, and compliance
2. **Enforce Invariants:** Cascade behaviors prevent orphaned records; explicit foreign key constraints maintain referential integrity
3. **Audit Everything:** Critical operations (verification, cancellation, refunds) logged in immutable audit trail
4. **Comply with Privacy:** Implement data retention policies; allow user requests for data deletion (GDPR, CCPA)
5. **Enable Recovery:** Soft-deleted records remain recoverable within grace period; regular backups enable point-in-time recovery

## User Lifecycle

### Creation

**Trigger:** User signs up with email, password, display name  
**Table:** `users`  
**Operations:**
```sql
INSERT INTO users (
  id, email, password_hash, display_name, status, 
  created_at, updated_at
) VALUES (
  gen_random_uuid(), 'user@example.com', 
  bcrypt_hash('password'), 'User Name', 'active',
  CURRENT_TIMESTAMP, CURRENT_TIMESTAMP
);
```
**Initial State:** `status = 'active'` (email verification may be deferred to optional feature; MVP assumes email is trustworthy)  
**Audit:** Log `UserRegistered` event with email and timestamp  
**Immutability:** `created_at` is immutable; never updated

---

### Activation

**State Before:** `status = 'active'` (no separate activation for MVP)  
**Modifications:** User may update profile (`bio`, `profile_picture_url`, `display_name`, `phone`, `locale`)  
**Audit:** Log profile updates; capture old/new values in audit log  
**Idempotency:** Updates are idempotent; `updated_at` is set to current timestamp on each update

---

### Artist Capability Activation

**Prerequisite:** User has `status = 'active'`  
**Trigger:** User applies for artist capability or creates first artwork  
**Operations:**
```sql
INSERT INTO artist_profiles (
  id, user_id, display_name, verification_status, allow_offers,
  created_at, updated_at
) VALUES (
  gen_random_uuid(), 'user-uuid', 'Artist Name', 'not_applied', false,
  CURRENT_TIMESTAMP, CURRENT_TIMESTAMP
);
```
**Initial State:** `verification_status = 'not_applied'`  
**Authorization:** Artist cannot publish artworks until `verification_status = 'approved'`  
**Audit:** Log artist profile creation; emit `ArtistProfileCreated` event

---

### Modification

**Allowed Changes:**
- Email (with re-verification, deferred to future)
- Password (reset via secure flow)
- Display name, bio, profile picture (immediate)
- Phone, locale (immediate)
- Metadata (flexible JSON)

**Constraints:**
- Email must remain unique among active users
- Soft-deleted users (deleted_at IS NOT NULL) may have duplicate emails (allows re-registration)
- Password changes create security audit log entry

**Audit:** Every update logged with actor_id, timestamp, old/new values

---

### Suspension

**Trigger:** Admin action (policy violation)  
**State Transition:** `status: active → suspended`  
**Operations:**
```sql
UPDATE users SET status = 'suspended', updated_at = CURRENT_TIMESTAMP 
WHERE id = 'user-uuid';

INSERT INTO audit_log (actor_id, target_type, target_id, action, payload)
VALUES ('admin-uuid', 'user', 'user-uuid', 'suspended', '{"reason": "..."}');
```
**Effect:**
- User cannot authenticate
- Existing orders remain visible to user
- Artist's artworks hidden from marketplace
- User can appeal (future feature)

**Recovery:** Admin can unsuspend by setting `status = 'active'`  
**Audit:** Log suspension reason and admin actor

---

### Soft Deletion (Account Closure)

**Trigger:** User requests account deletion or admin disables account  
**State Transition:** `status: * → deleted` AND `deleted_at IS NOT NULL`  
**Operations:**
```sql
UPDATE users 
SET status = 'deleted', deleted_at = CURRENT_TIMESTAMP, updated_at = CURRENT_TIMESTAMP 
WHERE id = 'user-uuid';

-- Cascade: mark artist profile as deleted
UPDATE artist_profiles SET deleted_at = CURRENT_TIMESTAMP WHERE user_id = 'user-uuid';

-- Cascade: soft-delete customer profile (optional cascade depends on policy)
UPDATE customer_profiles SET deleted_at = CURRENT_TIMESTAMP WHERE user_id = 'user-uuid';

-- Orders remain unaffected (preserve historical records)
-- Login is prevented (deleted_at IS NOT NULL)
```
**Grace Period:** 30 days (business policy) before hard deletion (optional); allows account recovery  
**Email Reuse:** After grace period, email becomes available for new registration  
**Audit:** Log deletion timestamp, reason (if provided), actor

**Privacy:** Delete PII from fields except those needed for audit/orders:
- Clear `phone`, `bio`, `profile_picture_url`
- Preserve `email` and `created_at` for audit trail

---

### Hard Deletion (Rare)

**Trigger:** Legal request (GDPR right-to-be-forgotten) or data retention policy expiry  
**Condition:** Only after grace period AND if no active business records reference user  
**Constraints:** Cannot hard-delete if user has:
- Active orders (RESTRICT via foreign key)
- Payments (RESTRICT via foreign key)
- Artists cannot be hard-deleted if they have order_items (RESTRICT)

**Policy:** FANNAN may implement hard deletion on multi-year schedule (e.g., 7 years post-deletion) for compliance, but this requires documented legal guidance.

**Note:** [COMPLIANCE DECISION REQUIRED] — Verify GDPR/CCPA deletion requirements with legal counsel. Current design supports soft-deletion with grace period; hard deletion deferred pending legal guidance.

---

### Recovery

**Window:** 30 days post-soft-deletion (configurable)  
**Operation:**
```sql
UPDATE users 
SET status = 'active', deleted_at = NULL, updated_at = CURRENT_TIMESTAMP 
WHERE id = 'user-uuid' AND deleted_at > (CURRENT_TIMESTAMP - INTERVAL '30 days');
```
**Audit:** Log recovery timestamp and actor (user or admin)

---

### Privacy & Security

- **Password:** Bcrypt or Argon2 hash; never log plain passwords
- **PII at Rest:** Encrypt sensitive fields if required by security policy (phone, address)
- **API Responses:** Exclude password_hash, deleted_at from customer-facing APIs
- **Audit:** Track login attempts, password resets, permission changes
- **Backup:** PII is backed up; encryption keys stored separately from encrypted data

---

### Retention

| Data | Duration | Reason |
|------|----------|--------|
| Active user records | Indefinite | Business operational need |
| Soft-deleted users | 7 years minimum | Tax/compliance, audit trail |
| Login attempts | 90 days | Security analysis |
| Password reset tokens | 24 hours (expiry) | Token security |

## Artist Profile & Verification Lifecycle

### Creation

**Trigger:** User applies for artist capability or creates first artwork  
**Table:** `artist_profiles`  
**Initial State:** `verification_status = 'not_applied'`  
**Operations:**
```sql
INSERT INTO artist_profiles (
  id, user_id, display_name, allow_offers, 
  verification_status, created_at, updated_at
) VALUES (
  gen_random_uuid(), 'user-uuid', 'Artist Name', false,
  'not_applied', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP
);
```
**Immutability:** `user_id` is immutable (1:1 constraint); cannot reassign profile to different user

---

### Profile Modification

**Allowed Updates:**
- `display_name` (artist storefront name)
- `public_bio` (markdown, HTML-sanitized in app)
- `allow_offers` (global offer setting; per-artwork override in artworks.allow_offers)
- `social_links` (JSONB: instagram, website, etc.)
- `location` (city/country for display)
- `shipping_policies` (JSONB, future feature)

**Constraint:** Display name must be non-empty and unique among artists (enforced at application layer)  
**Audit:** Log changes to sensitive fields (bio, location, offer policies)

---

### Verification State Machine

**States:** `not_applied` → `pending` → `approved | rejected` → `suspended (any state)`

#### Submission (not_applied → pending)

**Trigger:** Artist applies for verification or admin manually submits  
**Operations:**
```sql
UPDATE artist_profiles 
SET verification_status = 'pending', 
    verification_submitted_at = CURRENT_TIMESTAMP,
    updated_at = CURRENT_TIMESTAMP 
WHERE id = 'profile-uuid';

INSERT INTO audit_log (...) VALUES (..., 'artist_verification_submitted', '{"submitted_by": "artist"}');
```
**Submission Package:** Artist provides:
- Government ID or business license (uploaded to S3, not stored in DB)
- Business name and address
- Payout bank details (stored in external vault, not in DB)
- Intent statement (stored in metadata JSONB)

---

#### Approval (pending → approved)

**Trigger:** Admin reviews and approves  
**Operations:**
```sql
UPDATE artist_profiles 
SET verification_status = 'approved', 
    verification_decision_at = CURRENT_TIMESTAMP,
    verification_notes = 'Approved per policy X',
    updated_at = CURRENT_TIMESTAMP 
WHERE id = 'profile-uuid';

-- Artist can now publish artworks
INSERT INTO audit_log (...) VALUES (..., 'artist_verified', '{"approved_by": "admin-uuid", "decision_at": "..."}');

-- Emit event for notifications
INSERT INTO notifications (...) VALUES (..., 'artist_verified', 'You are approved to sell', ...);
```
**Consequence:** Artist can now publish artworks (authorization gate in application)  
**Audit:** Log approver identity, timestamp, notes

---

#### Rejection (pending → rejected)

**Trigger:** Admin rejects application  
**Operations:**
```sql
UPDATE artist_profiles 
SET verification_status = 'rejected', 
    verification_decision_at = CURRENT_TIMESTAMP,
    verification_notes = 'ID verification failed: reason',
    updated_at = CURRENT_TIMESTAMP 
WHERE id = 'profile-uuid';

-- Artist must reapply (cannot auto-retry)
INSERT INTO audit_log (...) VALUES (..., 'artist_verification_rejected', '{"rejected_by": "admin-uuid", "reason": "..."}');

-- Emit notification
INSERT INTO notifications (...) VALUES (..., 'artist_verification_rejected', 'Your application was not approved...', ...);
```
**Consequence:** Artist cannot publish (authorization gate blocks publish operations)  
**Reapplication:** Artist can reapply (transition rejected → not_applied via application flow); time delay recommended (e.g., 30 days before reapplication allowed)

**Audit:** Log rejection reason, approver, timestamp

---

#### Suspension (any state → suspended)

**Trigger:** Admin action (policy violation detected)  
**Operations:**
```sql
UPDATE artist_profiles 
SET verification_status = 'suspended', 
    updated_at = CURRENT_TIMESTAMP 
WHERE user_id = 'user-uuid';

-- Cascade: hide all artworks
UPDATE artworks SET status = 'suspended' WHERE artist_id = 'user-uuid';

-- Prevent new orders on artist's products
-- (enforced at application layer via policy)

INSERT INTO audit_log (...) VALUES (..., 'artist_suspended', '{"reason": "Policy violation: copyright infringement"}');
```
**Consequence:**
- Artist cannot create new listings
- Existing listings hidden
- New orders cannot be placed
- Existing orders unaffected (proceed normally)

**Appeal:** Artist can request appeal (future feature); admin can unsuspend

---

### Profile Deletion

**Hard Deletion:** Rare; only if artist profile never published artworks and has no orders  
**Soft Deletion via User Deletion:** Handled by user lifecycle (artist_profiles.deleted_at set on user deletion)  
**Preservation:** Artist's profile and verification decisions preserved in audit log for compliance

---

### Retention

| Data | Duration | Reason |
|------|----------|--------|
| Approved artist profiles | Indefinite | Active selling |
| Rejected/suspended profiles | 7 years | Audit trail, reapplication history |
| Verification submissions | 7 years | Compliance, dispute resolution |
| Verification notes | 7 years | Admin decision audit trail |

## Artwork Lifecycle

### Creation (Draft)

**Trigger:** Artist creates listing  
**Table:** `artworks`  
**Initial State:** `status = 'draft'`, `published_at = NULL`  
**Operations:**
```sql
INSERT INTO artworks (
  id, artist_id, title, type, supply_type, base_price, currency,
  allow_offers, status, created_at, updated_at
) VALUES (
  gen_random_uuid(), 'artist-uuid', 'Title', 'physical', 'unique',
  150.00, 'USD', false, 'draft', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP
);

-- Create accompanying inventory record
INSERT INTO inventory (
  id, product_id, quantity_total, quantity_available, reserved_quantity
) VALUES (
  gen_random_uuid(), 'artwork-uuid', 1, 1, 0
);
```
**Precondition:** Artist must have `verification_status = 'approved'` to later publish (but draft creation unrestricted)  
**Immutability:** `artist_id` is immutable; cannot reassign artwork to different artist  
**Audit:** Log artwork creation

---

### Modification (Draft/Published)

**Allowed Changes (Draft):**
- All fields except `artist_id`
- Price, title, description, metadata

**Allowed Changes (Published):**
- Description, bio, metadata (non-financial fields)
- **Restricted:** Price changes must not retroactively affect existing orders
  - Solution: Price changes only apply to future orders; existing orders preserve their `unit_price` snapshot
  - Audit: Log price changes with old/new values

**Example:**
```sql
-- Update base_price for new orders
UPDATE artworks SET base_price = 120.00, updated_at = CURRENT_TIMESTAMP 
WHERE id = 'artwork-uuid';

-- Existing order_items preserve their unit_price (immutable)
-- SELECT unit_price FROM order_items WHERE product_id = 'artwork-uuid';
-- Result: 150.00 (old price) for orders placed before change

INSERT INTO audit_log (...) VALUES (..., 'artwork_price_changed', 
  '{"product_id": "...", "old_price": 150.00, "new_price": 120.00}');
```

---

### Publication (draft → published)

**Trigger:** Artist publishes listing  
**Precondition:** Artist profile must have `verification_status = 'approved'`  
**Operations:**
```sql
UPDATE artworks 
SET status = 'published', published_at = CURRENT_TIMESTAMP, updated_at = CURRENT_TIMESTAMP 
WHERE id = 'artwork-uuid' AND artist_id = 'artist-uuid';

INSERT INTO audit_log (...) VALUES (..., 'artwork_published', '{"published_at": "..."}');
```
**Consequence:** Artwork becomes visible in marketplace search/browse  
**Immutability:** `published_at` is set once; never changed  
**Audit:** Log publication timestamp and actor

---

### Hiding (published → hidden)

**Trigger:** Artist temporarily hides listing (deliberate archival)  
**Operations:**
```sql
UPDATE artworks SET status = 'hidden', updated_at = CURRENT_TIMESTAMP 
WHERE id = 'artwork-uuid';

-- Release inventory holds (cancel pending offers, if any)
UPDATE negotiations SET expires_at = CURRENT_TIMESTAMP 
WHERE product_id = 'artwork-uuid' AND expires_at > CURRENT_TIMESTAMP;
```
**Consequence:** Artwork is not visible in marketplace but data is preserved  
**Reversibility:** Artist can republish (hidden → published) anytime  
**Audit:** Log hiding and reason (if provided)

---

### Suspension (published → suspended)

**Trigger:** Admin action (moderation: copyright, policy violation)  
**Operations:**
```sql
UPDATE artworks 
SET status = 'suspended', updated_at = CURRENT_TIMESTAMP 
WHERE id = 'artwork-uuid';

INSERT INTO moderation_actions (...) 
VALUES (..., 'artwork', 'artwork-uuid', 'suspend_artwork', 'Copyright claim verified');

INSERT INTO audit_log (...) VALUES (..., 'artwork_suspended_by_moderation', 
  '{"reason": "Copyright claim", "moderation_action_id": "..."}');

-- Notify artist
INSERT INTO notifications (...) VALUES (..., 'artwork_suspended', 'Your listing was suspended...', ...);
```
**Consequence:** Artwork hidden from marketplace; cannot be purchased  
**Appeal:** Artist can appeal (future feature)

---

### Archival (any state → archived)

**Trigger:** Artist deliberately archives (or sold out, artist deletes)  
**Operations:**
```sql
UPDATE artworks 
SET status = 'archived', updated_at = CURRENT_TIMESTAMP 
WHERE id = 'artwork-uuid';
```
**Consequence:** Not visible in marketplace; preserved for historical reference  
**Reversibility:** Can be unarchived

---

### Soft Deletion

**Trigger:** Artist deletes artwork or admin removes for compliance  
**Operations:**
```sql
UPDATE artworks SET deleted_at = CURRENT_TIMESTAMP, updated_at = CURRENT_TIMESTAMP 
WHERE id = 'artwork-uuid';

-- Cascade: media deleted (s3 files persist; metadata soft-deleted)
UPDATE product_media SET deleted_at = CURRENT_TIMESTAMP WHERE product_id = 'artwork-uuid';

-- Orders remain unaffected (preserved for audit trail)
```
**Constraint:** Cannot hard-delete if artwork has order_items (RESTRICT via FK)  
**Audit:** Log deletion timestamp, actor, reason

---

### Retention

| Data | Duration | Reason |
|------|----------|--------|
| Published artworks | Indefinite | Portfolio history, orders |
| Archived artworks | 5 years | Historical reference |
| Soft-deleted artworks | 7 years | Audit trail, dispute resolution |
| Artwork metadata changes | 7 years | Price history, description audit |

## Product Media Lifecycle

### Upload (Creation)

**Trigger:** Artist uploads image/video/PDF for artwork  
**Table:** `product_media`  
**Operations:**
```sql
-- Binary uploaded to S3 asynchronously
-- S3 path: s3://fannan-artworks/{artist_id}/{artwork_id}/{media_id}.{ext}

INSERT INTO product_media (
  id, product_id, media_type, s3_key, s3_url, mime_type, 
  width, height, alt_text, order_index, created_at
) VALUES (
  gen_random_uuid(), 'artwork-uuid', 'image', 
  'artworks/artist-uuid/artwork-uuid/media-001.jpg',
  'https://cdn.fannan.com/artworks/artist-uuid/artwork-uuid/media-001.jpg',
  'image/jpeg', 1920, 1440, 'Painting of ...',  
  0, CURRENT_TIMESTAMP
);
```
**Immutability:** `s3_key` is immutable; never changed  
**Audit:** Log upload timestamp, file size, mime type

---

### Modification

**Allowed Changes:**
- `alt_text` (accessibility)
- `order_index` (display order in gallery)
- URL (if CDN changes, but s3_key remains authoritative)

**Restrictions:** Cannot modify `s3_key`, `mime_type`, or dimensions

---

### Reordering (order_index)

**Trigger:** Artist reorders gallery images  
**Operations:**
```sql
UPDATE product_media 
SET order_index = 1, updated_at = CURRENT_TIMESTAMP 
WHERE id = 'media-uuid' AND product_id = 'artwork-uuid';
```
**Atomicity:** Batch reordering should be transactional (all-or-nothing)

---

### Deletion

**Trigger:** Artist removes image from listing  
**Operations:**

**Option A: Soft Delete (Recommended)**
```sql
UPDATE product_media SET deleted_at = CURRENT_TIMESTAMP WHERE id = 'media-uuid';
-- S3 object remains for audit/recovery; application excludes deleted_at IS NOT NULL
```

**Option B: Hard Delete + S3 Cleanup**
```sql
-- Delete from DB
DELETE FROM product_media WHERE id = 'media-uuid';

-- Schedule async S3 deletion (don't wait for completion)
-- Reason: S3 operations may fail; decouple from DB transaction
PUBLISH EVENT 's3-deletion-scheduled' WITH payload {media_id, s3_key};
```

**Cascade Behavior:** Deleting artwork cascades to product_media (ON DELETE CASCADE via FK)  
**Audit:** Log deletion, reason, actor

---

### Retention

| Data | Duration | Reason |
|------|----------|--------|
| Active media records | Indefinite | Artwork portfolio |
| Soft-deleted media | 5 years | Audit trail |
| S3 objects | 30-90 days post-deletion | Recovery window |
| S3 objects (archived artworks) | Indefinite or per policy | Portfolio history |

## Digital Assets Lifecycle

### Creation (Purchase Completion)

**Trigger:** Order status transitions to `paid`; digital artwork triggers entitlement issuance  
**Table:** `digital_assets`  
**Precondition:** Artwork must have `type = 'digital'`  
**Operations:**
```sql
-- Artist uploads digital file when creating artwork
INSERT INTO digital_assets (
  id, product_id, s3_key, file_size_bytes, checksum, 
  access_policy, max_downloads, expiry_days, created_at
) VALUES (
  gen_random_uuid(), 'digital-artwork-uuid',
  'artworks/artist-uuid/digital/asset-001.zip',
  5242880, 'sha256hash...', 
  '{"max_downloads": 5, "expiry_days": 30}', 5, 30,
  CURRENT_TIMESTAMP
);

-- On order completion, create download entitlement
INSERT INTO order_entitlements (
  id, order_id, digital_asset_id, downloads_remaining, expires_at, created_at
) VALUES (
  gen_random_uuid(), 'order-uuid', 'asset-uuid', 5,
  CURRENT_TIMESTAMP + INTERVAL '30 days', CURRENT_TIMESTAMP
);

PUBLISH EVENT 'digital-entitlement-issued' WITH payload {order_id, customer_id, asset_id};
```
**Immutability:** `s3_key`, `checksum`, `file_size_bytes` are immutable  
**Access Control:** Downloads tracked via `order_entitlements.downloads_remaining`; application enforces limits

---

### Modification

**Allowed Changes:** Access policy (max_downloads, expiry_days) can be updated before purchase; post-purchase changes affect only new orders  
**Restricted:** Cannot modify s3_key (would break delivery)

---

### Entitlement Tracking

**Table:** `order_entitlements` (implicit in design; tracks customer access)  
**Operations on Download:**
```sql
-- Customer initiates download
UPDATE order_entitlements 
SET downloads_remaining = downloads_remaining - 1 
WHERE order_id = 'order-uuid' AND digital_asset_id = 'asset-uuid';

-- If downloads_remaining = 0 or expires_at < CURRENT_TIMESTAMP, deny download
```
**Audit:** Log each download attempt (customer_id, timestamp, success/failure)

---

### Revocation (Refund Scenario)

**Trigger:** Order refunded; customer loses access  
**Operations:**
```sql
UPDATE order_entitlements 
SET downloads_remaining = 0, expires_at = CURRENT_TIMESTAMP 
WHERE order_id = 'order-uuid';

PUBLISH EVENT 'digital-entitlement-revoked' WITH payload {order_id, customer_id};
```
**Consequence:** Customer cannot download; existing downloads remain on customer's device  
**Audit:** Log revocation, reason (refund, policy violation)

---

### Retention

| Data | Duration | Reason |
|------|----------|--------|
| Digital asset records | Indefinite | Portfolio, entitlement history |
| Entitlement records | 7 years | Audit trail, dispute resolution |
| S3 objects | Indefinite (or per policy) | Delivery guarantee |
| Download logs | 1 year | Usage analytics, fraud detection |

## Inventory Lifecycle

### Creation

**Trigger:** Artwork created; inventory record created automatically  
**Table:** `inventory`  
**Operations:**
```sql
INSERT INTO inventory (
  id, product_id, quantity_total, quantity_available, reserved_quantity
) VALUES (
  gen_random_uuid(), 'artwork-uuid', 
  CASE WHEN supply_type = 'unique' THEN 1 ELSE 10 END,  -- configurable initial quantity
  CASE WHEN supply_type = 'unique' THEN 1 ELSE 10 END,
  0
);
```
**Immutability:** For `supply_type = 'unique'`, `quantity_total` must = 1 and is immutable  
**For `supply_type = 'quantity':** `quantity_total` can be updated (restocking)

---

### Reservation (Offer Acceptance / Checkout)

**Trigger:** Customer accepts negotiated offer OR adds to cart (not reserved in MVP)  
**Operations:**
```sql
-- When offer accepted, reserve inventory
UPDATE inventory 
SET reserved_quantity = reserved_quantity + 1,
    quantity_available = quantity_available - 1
WHERE product_id = 'artwork-uuid';

-- Invariant check: quantity_available >= 0 (enforced via CHECK constraint)
-- If fails, raise error; offer acceptance rolled back

INSERT INTO audit_log (...) VALUES (..., 'inventory_reserved', 
  '{"product_id": "...", "quantity": 1, "reason": "offer_accepted"}');
```
**Constraint:** `quantity_available + reserved_quantity <= quantity_total` (CHECK constraint)  
**Atomicity:** Reservation must be transactional with offer acceptance

---

### Decrement (Order Confirmed / Payment Succeeded)

**Trigger:** Order payment confirmed (COD order confirmed by seller)  
**Operations:**
```sql
UPDATE inventory 
SET quantity_total = quantity_total - 1,
    reserved_quantity = reserved_quantity - 1
WHERE product_id = 'artwork-uuid';

-- Invariant: quantity_available = quantity_total - reserved_quantity
-- (Application recalculates and verifies)

INSERT INTO audit_log (...) VALUES (..., 'inventory_sold', 
  '{"product_id": "...", "order_id": "...", "final_quantity": 0}');
```
**For Unique Products:** After sale, inventory.quantity_total = 0 (artwork is sold, no restock possible)  
**Audit:** Log final inventory state

---

### Release (Order Cancelled / Offer Expires)

**Trigger:** Order cancelled within grace period OR negotiated offer expires  
**Operations:**
```sql
UPDATE inventory 
SET reserved_quantity = reserved_quantity - 1,
    quantity_available = quantity_available + 1
WHERE product_id = 'artwork-uuid';

INSERT INTO audit_log (...) VALUES (..., 'inventory_released', 
  '{"product_id": "...", "reason": "order_cancelled"}');
```
**Expiry:** Reservations expire per negotiation agreement expiry (typically 24-48 hours)  
**Cleanup:** Batch job checks negotiations.expires_at and releases expired reservations

---

### Restocking (quantity-based)

**Trigger:** Artist restocks (only for `supply_type = 'quantity'`)  
**Operations:**
```sql
UPDATE inventory 
SET quantity_total = quantity_total + 20,
```

## Order Lifecycle

### Creation

**Trigger:** Customer completes checkout (negotiated agreement OR direct purchase)  
**Table:** `orders`, `order_items`  
**Preconditions:**
- All products available (quantity_available > 0 or reserved for negotiated offer)
- Customer has valid shipping address (if physical items)
- Total amount calculated correctly

**Operations:**
```sql
-- Atomically: create order + items + reserve inventory

BEGIN TRANSACTION;

INSERT INTO orders (
  id, buyer_id, status, total_amount, currency,
  shipping_required, shipping_address_id, payment_method,
  negotiated_agreement_id, created_at, updated_at
) VALUES (
  gen_random_uuid(), 'customer-uuid', 'created', 150.00, 'USD',
  true, 'address-uuid', 'cash_on_delivery', NULL,
  CURRENT_TIMESTAMP, CURRENT_TIMESTAMP
);

INSERT INTO order_items (
  id, order_id, product_id, artist_id, quantity, unit_price, total_price,
  offer_id, created_at
) VALUES (
  gen_random_uuid(), 'order-uuid', 'artwork-uuid', 'artist-uuid', 1,
  150.00, 150.00, NULL, CURRENT_TIMESTAMP
);

-- Decrement inventory
UPDATE inventory 
SET quantity_total = quantity_total - 1,
    reserved_quantity = reserved_quantity - 1
WHERE product_id = 'artwork-uuid';

-- Verify inventory constraint satisfied
-- If not, ROLLBACK entire transaction

COMMIT;

PUBLISH EVENT 'OrderCreated' WITH payload {order_id, customer_id, total_amount};
INSERT INTO notifications (...) VALUES (..., 'order_created', 'Order confirmed', ...);
```

**Initial Status:** `status = 'created'` (awaiting payment confirmation)

### Agreement Expiry & Auto-Cancellation

**Trigger:** Negotiated agreement expires (24 hours from acceptance) without order creation

```sql
WHERE expires_at < CURRENT_TIMESTAMP AND order_id IS NULL;

-- Release inventory
UPDATE inventory 
SET reserved_quantity = GREATEST(0, reserved_quantity - 1),
    quantity_available = quantity_available + 1 
WHERE product_id IN (
  SELECT product_id FROM negotiated_agreements 
  WHERE expires_at < CURRENT_TIMESTAMP AND order_id IS NULL

```

```sql

INSERT INTO search_index (
  id, product_id, title, description, artist_id, status, price,
  category_ids, tag_ids, published_at, created_at
)

  id, id, title, description, artist_id, status, base_price,
```

## Localization Lifecycle Addendum

### Translation resources and templates

Translation resources and message templates follow `draft -> published -> superseded/retired`. Publishing invalidates locale/versioned caches and emits a publication event. Superseded versions remain available for audit and rollback according to the existing audit retention policy.

### User-generated translations

Artwork, artist-profile, category, tag, and collection translations follow their source entity lifecycle. Source deletion or anonymization must cascade or anonymize subordinate translations; no orphan translation may remain. Missing Arabic or English content is valid and must not block source publication unless a separate product rule requires it.

### Notifications and historical rendering

At notification creation/send time, resolve the recipient locale, select the active channel template, and record `resolved_locale`, `fallback_locale` when applicable, `template_key`, `template_version`, and rendered content where historical display or audit requires it. Later translation changes must not rewrite sent notifications, emails, push payloads, orders, invoices, or audit records.

### Search and cache lifecycle

Localized content publication, edit, unpublish, and deletion invalidate locale-specific caches and trigger asynchronous search reindexing. Cache keys and ETags must vary by locale and resource/template version so Arabic content cannot be served to an English request or vice versa.

### Privacy and export

User-generated translations are included in account export and deletion/anonymization workflows. Browser/device locale detection is transient and is not retained as authoritative user data. Domain data such as prices, IDs, statuses, and financial records remains language-neutral and follows its existing retention policy.

## Backup & Recovery Strategy

### Backup Frequency

- **Production Database:** Daily full backups + hourly incremental (WAL archiving for PostgreSQL)
- **S3 Objects:** Versioning enabled; deleted objects recoverable within 90 days
- **Audit Logs:** Separate backup stream; stored in immutable archive (S3 with MFA-delete)

### Recovery Scenarios

**Scenario 1: Soft-Deleted User Recovery**
- User requests account recovery within 30-day grace period
- Operation: `UPDATE users SET deleted_at = NULL, status = 'active'`
- No data loss; all related records (orders, profiles, etc.) remain intact

**Scenario 2: Accidental Order Deletion**
- Order soft-deleted in error
- Recovery: Query `deleted_at IS NOT NULL`, restore via UPDATE
- Audit: Log recovery action and actor

**Scenario 3: Point-in-Time Recovery**
- Database corrupted or ransomware attack
- Recovery: Restore from clean daily backup; replay WAL until safe point-in-time
- Impact: Lose ~24 hours of data; audit logs preserved separately

**Scenario 4: S3 Media Recovery**
- Artist accidentally deletes artwork media
- Recovery: Restore from S3 object versioning (within 90 days)
- After 90 days: Unrecoverable (permanent deletion)
