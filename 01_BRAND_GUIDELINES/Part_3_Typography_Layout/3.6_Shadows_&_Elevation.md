# FANNAN Shadows & Elevation

FANNAN uses shadow with restraint. Elevation should feel warm, refined, and quietly functional rather than glossy or dramatic. The purpose of shadow in this system is to communicate hierarchy, separation, and interaction state while preserving the brand's minimal, premium character.

## Elevation Philosophy

- Keep shadows soft, low-contrast, and directional.
- Prefer subtle spread and blur over hard edges.
- Use elevation only when it clarifies a layer relationship.
- Combine shadow with border and radius changes for reliable depth cues.
- Keep overlays clearly separated from page content, but avoid heavy dark shadows.

## Elevation Scale

| Token | Purpose | Typical Use |
| --- | --- | --- |
| Elevation 0 | Flat surface | Base page background, inline content panels |
| Elevation 1 | Barely raised | Default cards, simple containers |
| Elevation 2 | Light separation | Hoverable cards, input groups, sticky sections |
| Elevation 3 | Clear foreground | Dropdowns, menus, side panels |
| Elevation 4 | Strong foreground | Floating buttons, drawers, elevated tool panels |
| Elevation 5 | High emphasis | Modals, dialogs, critical overlays |
| Modal | Maximum overlay depth | Full-screen blocking dialogs and focus states |
| Tooltip | Minimal floating depth | Short hint bubbles and hover labels |
| Dropdown | Menu depth | Select menus, action lists, popovers |
| Floating Button | Persistent action depth | Primary action buttons that float above content |

## Visual Hierarchy

Elevation in FANNAN should map directly to interaction importance:

| Level | Reading | Behavior |
| --- | --- | --- |
| Surface | Background and content plane | No shadow or only hairline separation |
| Interactive content | Cards, inputs, controls | Small lift on hover or focus |
| Menus and panels | Dropdowns, drawers, floating tool areas | Clear separation from content beneath |
| Blocking overlays | Modals and dialogs | Strongest shadow and background scrim |

Use shadow to support hierarchy, not replace it. Typography, spacing, and border treatment should still carry most of the visual structure.

## Border Strategy

Borders and shadows work together in this system.

| Surface Type | Border Strategy | Notes |
| --- | --- | --- |
| Flat page surfaces | No border or `1px` neutral border | Use when background separation is already strong |
| Cards | `1px solid rgba(15, 23, 42, 0.08)` | Keeps cards readable without over-relying on shadow |
| Inputs | `1px solid rgba(15, 23, 42, 0.12)` | Increase contrast on hover and focus |
| Dropdowns | `1px solid rgba(15, 23, 42, 0.10)` | Pair with elevation 3 |
| Modals | `1px solid rgba(15, 23, 42, 0.08)` | Helps define edges at high blur values |
| Floating buttons | No border or `1px solid rgba(255, 255, 255, 0.12)` | Keep shape clean and simple |

Border radius should soften elevation and make layers feel premium rather than mechanical.

## Radius System

| Token | Value | Use |
| --- | ---: | --- |
| `radius-sm` | 8px | Dense controls, chips, compact fields |
| `radius-md` | 12px | Buttons, inputs, menus, small cards |
| `radius-lg` | 16px | Standard cards, dropdowns, tool panels |
| `radius-xl` | 20px | Premium cards, dialogs, larger surfaces |
| `radius-2xl` | 24px | Modals, drawers, sheet containers |
| `radius-pill` | 999px | Pills, tool buttons, floating action shapes |

## State Shadows

### Hover Shadows

Hover states should create a small but noticeable lift.

- Cards move from elevation 1 to elevation 2.
- Buttons and icon buttons can gain a subtle halo or stronger outer shadow.
- Interactive panels should feel more tactile without looking detached from the page.

### Focus Shadows

Focus states must remain accessible and visible on all surfaces.

- Use a colored ring combined with a soft shadow.
- Keep the focus indicator outside the border so it is never hidden by the component fill.
- Avoid using shadow alone for focus because it may not be sufficiently distinct for keyboard users.

### Pressed State

Pressed states should feel grounded rather than sunken.

- Reduce blur and spread slightly.
- Remove part of the outer lift.
- Add a tiny downward translation if motion is used elsewhere in the system.

### Disabled State

Disabled surfaces should lose depth and contrast.

- Remove hover lift.
- Reduce shadow opacity toward zero.
- Pair with muted text and lower-contrast borders.

## Usage Guidance

| Component | Recommended Elevation | Notes |
| --- | --- | --- |
| Base cards | Elevation 1 | Default browsing surface |
| Hoverable cards | Elevation 2 | Lift on pointer hover only |
| Inputs and filters | Elevation 1 to 2 | Keep subtle to avoid visual noise |
| Dropdown menus | Elevation 3 | Must clearly sit above page content |
| Tooltips | Tooltip | Keep compact and unobtrusive |
| Floating action buttons | Floating Button | Reserve for primary persistent actions |
| Dialogs and modals | Modal | Strongest visual layer in the interface |

## Accessibility Notes

- Do not rely on shadow alone to communicate focus or selection.
- Ensure shadow contrast remains visible on warm and neutral backgrounds.
- Use enough separation between overlays and page content so depth is clear even for low-vision users.
- Keep disabled state changes obvious through opacity, contrast, and interaction removal.
- Test overlay elevation in both light and low-contrast contexts.

## Implementation Notes

- Prefer token-based shadows rather than one-off custom shadow values.
- Pair elevation changes with motion sparingly so the interface does not feel overstimulated.
- Keep borders and shadows coordinated: if the shadow gets stronger, the border can usually get lighter.
- In React components, expose elevation only where it helps system consistency, such as cards, menus, and overlays.
