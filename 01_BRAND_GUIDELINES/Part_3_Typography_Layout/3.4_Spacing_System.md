# FANNAN Spacing System

Spacing gives FANNAN its sense of composure. It creates a calm frame for artwork, makes related information feel intentionally grouped, and gives complex marketplace and dashboard tasks a predictable rhythm. Use the system consistently rather than solving local layout issues with one-off margins.

## The 8-point grid

FANNAN uses an **8-point grid** for structural spacing. Most dimensions are multiples of 8px. A 4px increment is allowed only for precise, compact adjustments—such as icon alignment or a tight text stack—where 8px would be visibly too large.

| Rule | Guidance |
| --- | --- |
| Default unit | Use 8px for gaps, padding, component separation, and section rhythm. |
| Precision unit | Use 4px only for small internal relationships or optical correction. |
| No invented values | Do not introduce 6px, 10px, 14px, 18px, or other arbitrary values. Choose the nearest token. |
| Responsive change | Increase page gutters and section spacing at wider ranges; do not compress internal control spacing below its token. |
| Direction | Use logical inline/block properties so the same spacing works in LTR and RTL. |

## Spacing tokens

Tokens use a numeric name equal to their pixel value. This makes design, Tailwind configuration, and implementation handoff unambiguous.

| Token | Value | Grid relationship | Use |
| --- | ---: | --- | --- |
| `space-0` | 0px | Reset | No gap; adjacent visual units intended to read as one, such as an image and its edge-to-edge frame. |
| `space-2` | 2px | Micro adjustment | Hairline visual offset, tightly coupled status dot, or optical correction only. Never use as general padding. |
| `space-4` | 4px | Half unit | Title-to-subtitle stack, icon optical adjustment, inline metadata separation. |
| `space-8` | 8px | 1 unit | Icon-to-label gap, related inline controls, compact stack inside a component. |
| `space-12` | 12px | 1.5 units | Input label to field, compact card text stack, small control-group gap. |
| `space-16` | 16px | 2 units | Standard compact padding, card grid gap on mobile, default field stack, mobile page gutter. |
| `space-20` | 20px | 2.5 units | Comfortable button-group gap, compact panel padding, small section sub-group. |
| `space-24` | 24px | 3 units | Default desktop/tablet grid gutter, standard card padding, related component separation. |
| `space-32` | 32px | 4 units | Large card/panel padding, filter groups, section heading to content. |
| `space-40` | 40px | 5 units | Compact page section, desktop page gutter, major component separation. |
| `space-48` | 48px | 6 units | Mobile section spacing, dialog padding on spacious layouts, primary content groups. |
| `space-56` | 56px | 7 units | Medium editorial breathing room or a deliberately generous panel gap. Use sparingly. |
| `space-64` | 64px | 8 units | Tablet section spacing, desktop card-region separation, page header to content. |
| `space-72` | 72px | 9 units | Large editorial transition; use when 64px feels crowded but 80px is too emphatic. |
| `space-80` | 80px | 10 units | Desktop section spacing, hero-to-content transition, major marketplace grouping. |
| `space-96` | 96px | 12 units | Major desktop section separation, campaign composition, generous dashboard page division. |
| `space-128` | 128px | 16 units | Rare, high-impact hero or campaign whitespace. Never use inside ordinary components. |

## How to choose a token

Use proximity to communicate relationship. The smaller the gap, the stronger the perceived connection.

| Relationship | Preferred tokens | Example |
| --- | --- | --- |
| Same item | 0, 2, 4, 8 | Product title and artist name; icon and label |
| Related controls or content | 12, 16, 20, 24 | Form fields in a group; card image to metadata |
| Separate components in one section | 24, 32, 40 | Filter bar to results; card groups in a panel |
| Distinct page sections | 48, 64, 80 | Product details to related work; gallery to artist story |
| Major narrative transition | 96, 128 | Campaign hero to first editorial section |

When in doubt, select a smaller token for elements that must be scanned together and a larger token for elements that can be understood independently. Do not use borders as a substitute for missing spatial grouping.

## Responsive spacing

Component-internal tokens generally remain stable. Page-level and section-level spacing expands as room increases.

| Context | Phone | Tablet | Desktop | Wide desktop |
| --- | ---: | ---: | ---: | ---: |
| Page inline gutter | 16px | 24px | 40px | 64px minimum outside capped container |
| Grid gutter | 16px | 24px | 24px | 32px where cards benefit |
| Small component gap | 8–16px | 8–16px | 8–16px | 8–16px |
| Standard component gap | 16–24px | 16–24px | 24–32px | 24–32px |
| Standard section gap | 48px | 64px | 80px | 96px |
| Major editorial gap | 64–80px | 80–96px | 96px | 128px |

Do not reduce touch-target padding to make a narrow layout fit. Reduce columns, stack content, or move secondary controls into an overflow pattern instead.

## Implementation guidance

- Use named spacing tokens in design files and code. A component should expose spacing variants such as `compact`, `default`, and `spacious`, rather than accepting arbitrary pixel margins.
- In Tailwind, extend the spacing scale with the listed values and use the same names across `gap`, `padding`, `margin`, `inset`, and logical spacing utilities. Keep page gutters and section spacing as semantic layout primitives.
- In React, prefer `Stack` for vertical rhythm, `Cluster` for wrapping inline groups, and `Grid` for two-dimensional layouts. Each primitive should own its gap so children do not accumulate competing margins.
- Use `gap` for sibling spacing whenever possible. It behaves predictably when items wrap, reorder, or are conditionally absent.
- Give components one owner for external spacing: the parent controls spacing between components; the component controls its internal padding and internal rhythm.
- Use `margin-inline`, `padding-inline`, `margin-block`, and `padding-block` rather than left/right-specific rules. This preserves the intended rhythm in Arabic RTL interfaces.

## Review checklist

| Check | Pass condition |
| --- | --- |
| Token compliance | Every gap and padding value matches an approved token. |
| Relationship clarity | Tighter gaps signal stronger relationships; separate groups have visibly larger space. |
| Responsive rhythm | Page and section space expands by range without shrinking touch targets or internal control spacing. |
| Artwork breathing room | Gallery and featured work are not crowded by metadata, controls, or neighbouring cards. |
| Direction | The layout keeps equivalent inline spacing and order in RTL and LTR. |
| Zoom and overflow | Text growth does not collapse padding, hide dialog actions, or create accidental page overflow. |
