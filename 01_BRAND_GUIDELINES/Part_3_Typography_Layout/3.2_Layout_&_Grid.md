# FANNAN Layout & Grid

FANNAN’s layout system is designed to frame artwork with calm, deliberate space. It gives a product card, an artist story, and a dense dashboard a shared underlying order while allowing each experience to feel appropriately open or focused. The grid should be felt before it is noticed.

## Layout principles

- **Artwork leads.** Give images and objects room to breathe; do not fill every available column with interface chrome.
- **Consistency creates trust.** Align repeated elements—titles, prices, filters, cards, metadata—to the same grid edges.
- **Hierarchy before density.** Use width, span, and whitespace to establish importance before adding borders or decoration.
- **Mobile is a distinct composition.** Reorder and simplify deliberately; do not merely shrink desktop columns.
- **RTL-ready by default.** Use logical start/end edges and direction-aware ordering. A layout must retain its intent in Arabic and English.

## Base spacing grid

### 4pt grid: the precision unit

The **4pt grid** is the smallest spatial increment. Use it for fine alignment and compact component spacing.

| Token | Value | Typical use |
| --- | ---: | --- |
| 1 | 4px | Icon-to-label gap, hairline adjustment, compact internal spacing |
| 2 | 8px | Tight metadata stack, icon button padding increment |
| 3 | 12px | Input internal gap, compact card padding |
| 4 | 16px | Default small spacing, mobile card padding |
| 5 | 20px | Control group gap |
| 6 | 24px | Standard gutter at compact widths |

### 8pt grid: the composition unit

The **8pt grid** is the default unit for page layout, component separation, and section rhythm. Values should be multiples of 8px unless a 4px precision adjustment is needed.

| Token | Value | Typical use |
| --- | ---: | --- |
| 1 | 8px | Small related-item gap |
| 2 | 16px | Card gap, mobile gutter |
| 3 | 24px | Default page gutter, component separation |
| 4 | 32px | Card padding, section sub-spacing |
| 5 | 40px | Compact section spacing |
| 6 | 48px | Tablet section spacing |
| 8 | 64px | Desktop section spacing |
| 10 | 80px | Hero-to-content transition |
| 12 | 96px | Major desktop section separation |
| 16 | 128px | Large editorial or campaign breathing room |

Do not create new one-off values when a nearby grid token works. Exception: optical alignment of artwork, icons, or typography may use a 4px adjustment after visual review.

## Containers and page margins

Every page uses a centered container with responsive side padding. `Max content width` is the outermost standard content boundary; individual reading content may be narrower.

| Range | Viewport | Container behaviour | Side margins / padding | Max content width |
| --- | --- | --- | ---: | ---: |
| Mobile | `< 640px` | Full width | 16px | None; fill available width |
| Tablet | `640–1023px` | Fluid, centered | 24px | 960px |
| Desktop | `1024–1439px` | Fluid, centered | 40px | 1280px |
| Wide desktop | `≥ 1440px` | Centered, capped | 64px minimum | 1440px |

The 1440px cap is for marketplace and dashboard content. A campaign image may bleed to the viewport edge, but its text and controls must return to the standard container.

```text
Viewport
┌──────────────────────────────────────────────────────────────────────┐
│ margin │                  max-width container                  │margin │
│        │  content aligns here; backgrounds may extend outward  │       │
└──────────────────────────────────────────────────────────────────────┘
```

Use `max-width: 1440px` as the default outer cap. Use `1280px` for product browsing and most editorial listing content when a tighter composition helps products feel curated.

| Range | Columns | Gutter | Outer margin | Recommended use |
| --- | ---: | ---: | ---: | --- |
| Mobile | 4 | 16px | 16px | One-column content; 2-column product tiles when imagery remains legible |
| Tablet | 8 | 24px | 24px | Flexible editorial and marketplace layouts; 2–4 card galleries |
| Desktop | 12 | 24px | 40px | Primary web grid for browsing, product, and dashboard pages |
| Wide desktop | 12 | 32px | 64px minimum | Large screens; preserve capped content and avoid over-wide cards |

│   16     │ C1 │ C2 │ C3 │ C4 │    16     │
└──────────┴────┴────┴────┴────┴───────────┘

The grid is a placement system, not a mandate to draw lines. A component may span any number of columns; its internal spacing remains governed by the 4pt/8pt grids.

## Standard column spans

| Pattern | Mobile | Tablet | Desktop | Use |
| --- | --- | --- | --- | --- |
| Full content | 4/4 | 8/8 | 12/12 | Page sections, full-width media inside container |
| Main + aside | 4/4 stacked | 5 + 3 | 8 + 4 | Article details, account settings, supporting information |
| Narrow reading block | 4/4 | 6/8 | 7/12 | Artist stories, policy pages, long-form descriptions |
| Split feature | 4/4 stacked | 4 + 4 | 6 + 6 | Image-and-copy feature or editorial hero |
| Feature + support | 4/4 stacked | 5 + 3 | 7 + 5 | Curated collection with supporting panel |

## Reading width

Readable text should not automatically span its parent container.

| Content | Maximum measure | Grid guidance |
| --- | ---: | --- |
| Long-form body copy | 680px | 7 desktop columns or 6 tablet columns |
| Product description | 560px | Constrain inside the product information span |
| Short editorial lead | 760px | Up to 8 desktop columns |
| Dense dashboard table | 1200px | Use full desktop container with horizontal overflow only as a last resort |

Aim for approximately 45–75 Latin characters or 22–38 Arabic characters per line. Arabic and Latin text may require different practical caps; test the real content rather than enforcing a fixed character count.

## Whitespace and visual rhythm

Whitespace is active structure, not unused space. It separates different ideas, groups related information, and protects the premium feel of the marketplace.

| Relationship | Preferred spacing | Example |
| --- | ---: | --- |
| Within a control | 8–12px | Icon and button label |
| Related text stack | 4–8px | Artwork title and artist name |
| Card content group | 16px | Image metadata to price/action area |
| Adjacent components | 24–32px | Filter row to results grid |
| Section within a page | 48px mobile; 64px desktop | Collection heading to product gallery |
| Major page transition | 80px mobile; 96–128px desktop | Hero to first content section |

Use more whitespace around singular, high-value work and less around repeated browse cards. Vertical rhythm should be built from section spacing first; avoid random margins added independently by child components.

## Gallery layout

Gallery pages should invite browsing while maintaining enough image size to judge material, colour, and craft.

| Range | Default layout | Card gap | Notes |
| --- | --- | ---: | --- |
| Mobile | 2 columns; 1 column for immersive editorial work | 16px | Use consistent aspect ratios within a row; allow a featured piece to span 2 columns. |
| Tablet | 3 columns, or 2 columns for large work | 24px | Filters may sit above the grid. |
| Desktop | 4 columns; 3 columns for larger collectible work | 24px | Filter rail can occupy 3 columns; gallery occupies 9. |

```text
Desktop gallery — filter rail + 9-column results
┌───────────────┬──────────────────────────────────────────────────────┐
│  Filters      │  [ artwork ]  [ artwork ]  [ artwork ]                │
│  3 columns    │  [ artwork ]  [ artwork ]  [ artwork ]                │
│               │  results grid: 9 columns                              │
└───────────────┴──────────────────────────────────────────────────────┘

Mobile gallery — feature followed by browse tiles
┌──────────────────────────────────────┐
│          featured artwork             │  4 columns
├───────────────────┬──────────────────┤
│      artwork      │      artwork      │  2 + 2 columns
└───────────────────┴──────────────────┘
```

Avoid masonry by default: uneven rows make price and title scanning harder. Use a curated masonry treatment only for editorial storytelling, where a deliberate sequence and accessible reading order are provided.

## Product page layout

| Range | Media | Information | Behaviour |
| --- | --- | --- | --- |
| Mobile | Full 4-column image gallery | Full-width content below | Sticky purchase action may appear after price; preserve safe-area padding. |
| Tablet | 5 columns | 3 columns | Media and details align at their top edges; thumbnails may sit below. |
| Desktop | 7 columns | 5 columns | Keep purchase information visible while reviewing media when space permits. |

```text
Desktop product page — 7 + 5
┌─────────────────────────────────┬───────────────────────────────────┐
│                                 │ Artwork title                     │
│         media gallery           │ Artist · price · availability     │
│          7 columns              │ Options and primary action        │
│                                 │ 5 columns                         │
└─────────────────────────────────┴───────────────────────────────────┘
```

Product information order is title, artist, price, availability, choices, primary action, then detail. On mobile, do not force a side-by-side layout; users need large media and an uninterrupted purchase path.

## Artist profile layout

| Range | Layout | Notes |
| --- | --- | --- |
| Mobile | Stacked identity, story, and work | Avatar and identity sit above a concise bio and actions. |
| Tablet | Identity/biography 3 columns + work 5 columns | Keep the bio readable; do not make it a narrow sidebar. |
| Desktop | Identity/biography 4 columns + portfolio 8 columns | Profile details may be sticky within the desktop column if they remain fully accessible. |

```text
Desktop artist profile — 4 + 8
┌──────────────────────┬──────────────────────────────────────────────┐
│ portrait / identity  │ portfolio heading                             │
│ biography            │ [ work ] [ work ] [ work ]                    │
│ links and categories │ [ work ] [ work ] [ work ]                    │
└──────────────────────┴──────────────────────────────────────────────┘
```

Use a constrained reading block for the artist’s narrative, even when the identity column is wide. The portfolio should begin on a clear grid edge and use the gallery rules above.

## Dashboard layout

Dashboards optimise for clarity and task completion, while retaining FANNAN’s generous rhythm.

| Range | Navigation | Main content | Notes |
| --- | --- | --- | --- |
| Mobile | Bottom navigation or compact top menu | 4 columns, stacked modules | Prioritise key status and one primary action; tables become cards or a focused detail view. |
| Tablet | Collapsible rail | 8 columns | Summary cards commonly use 4 + 4 or 2-column arrangements. |
| Desktop | Persistent 3-column navigation rail | 9-column workspace | Use a 12-column outer grid; allow dense data regions to span all 9 workspace columns. |

```text
Desktop dashboard — 3 + 9
┌───────────────┬──────────────────────────────────────────────────────┐
│ Navigation    │ Page title + primary action                          │
│ 3 columns     ├──────────────────┬──────────────────┬────────────────┤
│               │ summary card     │ summary card     │ summary card   │
│               ├──────────────────────────────────────────────────────┤
│               │ data / activity / inventory workspace                │
└───────────────┴──────────────────────────────────────────────────────┘
```

Do not compress a data table until its columns become unreadable. On mobile, convert it to a semantic list of records with the most important value first and a detail route for the remainder.

## Responsive behaviour

- Stack split layouts below tablet unless both sides remain useful at half width.
- Preserve content order in the DOM when reordering visually. For RTL, use logical direction rather than duplicating markup.
- Move filters from a persistent desktop rail to a triggerable mobile sheet; retain active-filter count and clear controls.
- Let imagery become full-bleed on mobile only when it strengthens the work. Keep text and actions inside page margins.
- Reduce columns before reducing gutters below 16px. A crowded 4-column grid is less usable than a confident 2-column grid.
- Keep touch targets at least 44 × 44px, including icon-only controls embedded in a grid.
- Prevent horizontal page scrolling; intentional horizontal scrolling must be visibly indicated and keyboard accessible.

## Implementation notes

- Treat layout as reusable primitives: `Container`, `PageGrid`, `Section`, `Stack`, `Cluster`, and page-specific templates. Components should request a span or layout variant, not set arbitrary page margins.
- Use CSS Grid for page, gallery, and dashboard structure. Use Flexbox for one-dimensional alignment such as button groups, metadata rows, and navigation items.
- Use logical CSS properties (`margin-inline`, `padding-inline`, `inset-inline-start`) and `dir` on the document or relevant subtree. Avoid left/right-specific geometry.
- Keep container padding owned by the container. A child section should not add a second competing horizontal margin.
- Define image aspect ratios intentionally; reserve space before images load to prevent layout shift.
- Keep header, sticky purchase areas, and dashboard rails within their own stacking contexts. Check that focus targets are not hidden beneath them.

## Tailwind recommendations

- Define named screen ranges for mobile-first usage: base, `sm` (640px), `lg` (1024px), and a wide desktop range at `2xl` (1440px). Use existing Tailwind ranges only if they map to these decisions consistently.
- Extend spacing only with the 4px and 8px tokens. Prefer semantic component classes or variants over scattered arbitrary margin values.
- Add container presets for marketplace (`1280px`), standard (`1440px`), and reading (`680px`) contexts. Pair each with responsive inline padding.
- Use grid utilities for the standard 4/8/12-column systems and explicit spans for templates. Keep gutters consistent by using a single responsive gap value per parent grid.
- Use direction-aware variants or logical-property utilities for RTL. Validate the final compiled CSS rather than assuming `rtl:` affects layout ordering correctly.
- Use aspect-ratio utilities for gallery cards and responsive order utilities only when the resulting keyboard and screen-reader order remains correct.

## React recommendations

- Build page templates from layout primitives and pass content through slots/children; do not embed page-level column math inside product cards or typography components.
- Make grid spans declarative through named variants such as `product`, `artist-profile`, and `dashboard`, with an escape hatch reserved for reviewed templates.
- Render the same content order for all breakpoints. If a mobile layout needs a materially different interaction, use one accessible component with responsive presentation before creating duplicated desktop/mobile markup.
- Keep filter state, sorting, and pagination outside visual grid components so the gallery can change columns without losing state or focus.
- When route transitions or filter changes alter the grid, announce result counts and preserve a sensible focus target. Do not move focus simply because the number of columns changed.
- Test each template with long Arabic names, short Latin labels, missing images, high zoom, and both LTR/RTL direction before release.
