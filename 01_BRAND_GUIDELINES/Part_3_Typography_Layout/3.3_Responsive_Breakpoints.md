# FANNAN Responsive Breakpoints

FANNAN is mobile-first. Each breakpoint protects artwork, comfortable reading, and a clear purchase or management path. Breakpoints respond to available space, not device models; test every template in both Arabic RTL and English LTR.

## Device categories

| Category | Viewport range | Design intent |
| --- | --- | --- |
| Phone | 320–639px | Focused browsing, clear actions, stacked content |
| Tablet | 640–1023px | More exploration space and touch-friendly multi-column layouts |
| Laptop | 1024–1279px | Full navigation and compact workspace layouts |
| Desktop | 1280–1439px | Comfortable editorial scale, rails, and browse grids |
| UltraWide | 1440px+ | Capped content with more breathing room, never uncontrolled line length |

## Breakpoint contract

All widths are minimum viewport widths and remain active until the next range. Base styles must work at 320px without horizontal page scrolling. The 375px, 390px, and 480px sizes are mandatory QA widths, not default media-query targets.

| Token | Min width | Tailwind recommendation | Category |
| --- | ---: | --- | --- |
| `xs` | 320px | Base styles; optional custom `xs` | Small phone |
| `sm` | 640px | `sm` | Tablet entry |
| `md` | 768px | `md` | Tablet |
| `lg` | 1024px | `lg` | Laptop |
| `xl` | 1280px | `xl` | Desktop |
| `2xl` | 1440px | Custom `2xl` | Large desktop |
| `3xl` | 1536px | Custom `3xl` | UltraWide entry |
| `4xl` | 1920px | Custom `4xl` | UltraWide |

## Global layout rules

| Concern | Phone | Tablet | Laptop and above |
| --- | --- | --- | --- |
| Page gutter | 16px | 24px | 40px; 64px minimum outside a capped container at 1440px+ |
| Grid | 4 columns | 8 columns | 12 columns |
| Grid gutter | 16px | 24px | 24px; 32px at wide desktop where card scale benefits |
| Section spacing | 48px | 64px | 80px; 96–128px for major editorial transitions |
| Long-form measure | Fluid within gutter | Maximum 680px | Maximum 680px; lead copy up to 760px |
| Touch target | Minimum 44 × 44px | Minimum 44 × 44px | Keep 44px wherever touch is possible |

## Typography scaling summary

| Style family | 320–639px | 640–1023px | 1024px+ |
| --- | --- | --- | --- |
| Display XXL / XL / L | 48 / 40 / 32px | 64 / 52 / 40px | 80 / 64 / 48px |
| H1 / H2 / H3 | 32 / 28 / 24px | 36 / 32 / 26px | 40 / 36 / 28px |
| Body XL / Large / Medium | 18 / 16 / 15px | 19 / 17 / 16px | 20 / 18 / 16px |
| Body Small / Label / Button | 13 / 13 / 14px | 14 / 13 / 14px | 14 / 14 / 15px |

Keep the named typography token’s line height, weight, and tracking at all ranges. Never tighten text merely to force it into a smaller component.

## Component behaviour

| Component | Phone | Tablet | Laptop and above |
| --- | --- | --- | --- |
| Header | Compact logo, search/action icons, sheet menu | Key links or tabs can appear | Full navigation, search, account, and bag actions |
| Filters | Trigger opens a sheet with active-filter count | Collapsible rail or horizontal filter row | Persistent 3-column rail on browse-heavy pages |
| Product detail | Media then stacked details; sticky action if helpful | 5 + 3 media/details split | 7 + 5 split; details may be sticky |
| Artist profile | Identity and portfolio stack | 3 + 5 split | 4 + 8 identity/portfolio split |
| Gallery | 2-up default | 3-up default | 4-up default; 3-up for large work |
| Data tables | Record cards and detail view | Scrollable table with primary column | Full table with prioritised columns |
| Forms | One column | Two columns for related fields | Two columns; maximum three for short grouped fields |
| Dashboard | Priority-first stacked modules | Collapsible rail and 2-up summaries | Persistent 3-column rail and 9-column workspace |

## Image rules

Reserve an image’s aspect-ratio box before it loads. Use responsive image sources based on the rendered container rather than the viewport, and never crop artwork in a way that hides its essential subject.

| Context | Phone | Tablet | Desktop / UltraWide |
| --- | --- | --- | --- |
| Marketplace card | 1:1 or 4:5, 2-up | 1:1 or 4:5, 3-up | 1:1 or 4:5, 4-up |
| Featured work | Full-width 4:5 or 16:10 | 4:3 or 3:2 | 3:2 or 16:9 when composition permits |
| Product gallery | Full-width primary media | 5-column media region | 7-column media region |
| Artist portrait | 1:1, full/half width | 3-column identity region | 4-column identity region |
| Dashboard thumbnail | Minimum 48px square | 48–64px square | 64px where recognition benefits |

## Implementation and QA

- Define page grid and container primitives centrally; children may span columns but must not invent page margins.
- Prefer fluid widths plus a `max-width` between breakpoint ranges. Add 375px/390px/480px queries only for evidence-based component failures.
- Use CSS logical properties and `dir` so RTL mirrors layout intent without duplicated markup.
- Keep DOM order aligned to the mobile reading order. Do not rely on visual reordering that confuses keyboard or screen-reader users.
- In Tailwind, define the custom 1440px, 1536px, and 1920px aliases centrally. Use mobile-first semantic component variants rather than repeated arbitrary widths.
- In React, preserve filter, table-selection, and form state when a rail becomes a sheet or a table becomes records on resize.
- Test 320px, 375px, 390px, 480px, 768px, 1024px, 1280px, 1440px, and 1920px; test 200% zoom, slow image/font loading, keyboard focus, safe areas, and both LTR/RTL content.

## Release checklist

| Check | Pass condition |
| --- | --- |
| Overflow | No horizontal page scrolling from 320px to 1920px, except intentional accessible scroll regions |
| Alignment | Headings, rails, cards, and primary actions align to the correct 4/8/12-column grid |
| Reading comfort | Body text stays within its measure cap and retains comfortable line height |
| Images | Correct source size, reserved space, and artist-safe crop are used |
| Navigation | Every route and action works by touch, keyboard, and screen reader |
| Direction | Arabic RTL and English LTR have equivalent hierarchy, spacing, and functional order |
