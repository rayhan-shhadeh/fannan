# 6.16 Admin API

## Scope
The Admin API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/admin`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Admin/moderator/support roles from 5.5.

**Authorization:** Every endpoint evaluates explicit permission and resource scope; support views are minimized; destructive actions require reason and audit. All access checks are server-side and use the identity/role model in unavailable Section 5.5; do not infer role or ownership from request fields.

## Endpoint inventory
GET /admin/users; PATCH /admin/users/{id}/status; GET /admin/products; POST /admin/products/{id}/moderate; GET /admin/orders; POST /admin/orders/{id}/refund; GET /admin/audit-events; GET /admin/metrics. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Admin list representations are minimized and paginated. Commands include `{reason,version}` where applicable and return operation/audit IDs. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Permission, reason, target state, version, refund/order constraints, export limits; no arbitrary query/filter injection. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Destructive commands require Idempotency-Key and If-Match; exports are asynchronous and scoped. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
Events: AdminActionRecorded, UserSuspended, ProductModerated, RefundRequested; audit record is immutable. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
MFA/step-up and role truth defer to 5.5; least privilege, IP/session controls, full audit, no bulk destructive default. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
