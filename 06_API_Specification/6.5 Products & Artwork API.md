# 6.5 Products & Artwork API

## Scope
The Products & Artwork API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/products`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Public buyer; artist owner; admin/moderator.

**Authorization:** Published product reads are public. Draft/edit/archive operations require owning artist or catalog permission; purchase availability is server-derived. All access checks are server-side and use the identity/role model in unavailable Section 5.5; do not infer role or ownership from request fields.

## Endpoint inventory
GET /products; POST /artists/me/products; GET /products/{id}; PATCH /artists/me/products/{id}; POST /products/{id}/publish; POST /products/{id}/archive; POST /products/{id}/availability. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Product `{id,artistId,title,description,price:{amount,currency},media,categoryIds,dimensions,stock,status,version}`. Create example includes title, price, media IDs, category IDs. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Price non-negative/currency, dimensions/weight units, stock integer, media ownership, category existence, publish completeness. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Create/publish/archive and stock updates require keys; If-Match prevents lost edits. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
ProductDrafted, ProductPublished, ProductPriceChanged, InventoryAdjusted, ProductArchived. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
Prevent price tampering at checkout; ensure unpublished media is not public; authorization on artist ownership. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
