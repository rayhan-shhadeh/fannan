# 6.1 API Conventions

## Resource and naming rules
Use plural lowercase nouns (`/products`, `/orders`), nested paths only for ownership or a bounded action (`/users/me/addresses`, `/orders/{id}/cancel`). Use hyphenated query names. Actions are explicit verbs only where a state transition is not naturally represented by `PATCH` (`/checkout/quote`, `/payments/{id}/confirm`). Avoid RPC-shaped nouns and leaking module/database names.

## Headers
Required: `Accept`, `Content-Type` for bodies. Recommended: `Authorization: Bearer <access-token>`, `X-Request-Id`, `Idempotency-Key` for documented commands, `If-Match` for concurrency. Responses include `X-Request-Id`, `ETag` where supported, and `Retry-After` on 429/503.

## Validation and errors
Unknown fields are rejected on commands; omitted fields mean unchanged on PATCH and `null` is allowed only where a schema says so. Trim user-entered text, normalize email case, enforce UTF-8 and maximum lengths, and validate enum/currency/quantity/range before authorization side effects. Common codes: `400 INVALID_REQUEST`, `401 UNAUTHENTICATED`, `403 FORBIDDEN`, `404 NOT_FOUND`, `409 CONFLICT`/`VERSION_CONFLICT`, `410 GONE`, `422 VALIDATION_ERROR`, `429 RATE_LIMITED`, `500 INTERNAL_ERROR`, `502 PROVIDER_ERROR`, `503 TEMPORARILY_UNAVAILABLE`.

## Pagination, filtering, sorting
List requests accept `limit` (default 20, max 100), opaque `cursor`, allow-listed filters, and allow-listed sort values. Cursors encode position and filter fingerprint; invalid or expired cursors return `400 INVALID_CURSOR`. Do not infer authorization from counts. Search has its own relevance sort; see [6.7](6.7%20Search%20API.md).

## State and concurrency
State changes are commands, validated against the transition tables in domain documents. `PATCH` cannot bypass a transition. Use ETags/versions for concurrent edits. A response may be `202` when work is asynchronous; it includes a status resource or operation ID.

## Idempotency and webhooks
Commands with money, inventory, order, offer, or external delivery effects require `Idempotency-Key`. Keys are scoped to actor + route and retained at least the documented payment/order reconciliation window. Webhook receivers authenticate signatures, tolerate retries, persist event IDs, and return `2xx` only after durable acceptance.

## Examples and privacy
Examples use fictitious opaque IDs. Redact PII, payment data, access tokens, and provider payloads in logs. See 5.13 Security Architecture (source directory absent) and 5.14 Observability & Logging (source directory absent).

## Blocking source dependency
The required Sections 03, 04, and 05 source directories are absent from this repository. This document preserves unresolved authority, permission, data-model, and architecture questions as open decisions; implementation must not infer them from this API specification.
