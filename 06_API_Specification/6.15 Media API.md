# 6.15 Media API

## Scope
The Media API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/media`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Authenticated owner; public reader of published references; admin/moderator.

**Authorization:** Upload authorization is checked before issuing a presigned URL; only owner or authorized editor can mutate metadata/delete. All access checks are server-side and use the identity/role model in unavailable Section 5.5; do not infer role or ownership from request fields.

## Endpoint inventory
POST /media/uploads; POST /media/uploads/{id}/complete; GET /media/{id}; PATCH /media/{id}; DELETE /media/{id}; POST /media/{id}/moderate. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Media `{id,kind,mimeType,size,variants,status,url,ownerId}`; upload response gives short-lived presigned target and upload ID, not storage credentials. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
MIME/extension allow-list, size/dimensions, virus/content scan, ownership, completion checksum, variant availability. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Create/complete/delete/moderate use keys; completion is safe to retry; URLs expire. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
State: initiated ? uploaded ? scanning ? ready or rejected/deleted. Events: MediaUploaded, MediaReady, MediaRejected. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
Short-lived scoped URLs, content disarm/scan, no arbitrary storage paths, redact EXIF where policy requires. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
