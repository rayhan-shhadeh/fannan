# 6.3 Users & Profiles API

## Scope
The Users & Profiles API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/users`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Authenticated user; admin for support; public profile viewer where visibility permits.

**Authorization:** A user reads/updates only their profile and addresses; admins use scoped support permission; artist profile editing is covered by [6.4]. All access checks are server-side and use the identity/role model in the missing Section 05 authentication/authorization source; do not infer role or ownership from request fields.

## Endpoint inventory
GET /users/me; PATCH /users/me; GET /users/{id}; GET/POST/PATCH/DELETE /users/me/addresses; PATCH /users/me/preferences. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
User `{id,displayName,bio,avatarMediaId,locale,timezone,roles}`; address never returned to another user; PATCH example `{ "displayName":"Mona" }`. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Display name/bio lengths, locale/timezone allow-list, address country/postal validation, unique defaults, consent/preferences validation. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Profile PATCH supports If-Match; address creation uses key to prevent duplicates. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
UserProfileUpdated, AddressAdded, AddressRemoved, PreferencesChanged. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
Field-level privacy; prevent IDOR; redact address/contact data; audit admin reads. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
