# 6.4 Artists API

## Scope
The Artists API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/artists`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Public visitor/customer; authenticated artist; admin/moderator.

**Authorization:** Public reads published artist profiles. An artist owns their profile, portfolio metadata, and submission workflow; admin moderates. All access checks are server-side and use the identity/role model in unavailable Section 5.5; do not infer role or ownership from request fields.

## Endpoint inventory
GET /artists; GET /artists/{id}; PATCH /artists/me; POST /artists/me/applications; GET /artists/me/dashboard; POST /artists/{id}/follow; DELETE /artists/{id}/follow. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Artist `{id,displayName,slug,statement,location,avatarMediaId,status,links}`; application `{statement,portfolioMediaIds}`. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Slug uniqueness, text/media limits, application completeness, published status, follow self-check. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Application and portfolio mutation keys; profile uses If-Match. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
ArtistApplicationSubmitted, ArtistApproved, ArtistSuspended, ArtistFollowed. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
Moderation and visibility checks; signed media references only; protect private application data. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
