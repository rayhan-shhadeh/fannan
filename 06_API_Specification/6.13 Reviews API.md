# 6.13 Reviews API

## Scope
The Reviews API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/reviews`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Authenticated verified buyer; public reader; admin moderator.

**Authorization:** A buyer may review only an eligible delivered order item and may edit/delete within policy. Public reads show approved reviews; moderation is admin-only. All access checks are server-side and use the identity/role model in the missing Section 05 authentication/authorization source; do not infer role or ownership from request fields.

## Endpoint inventory
GET /products/{id}/reviews; POST /orders/{id}/items/{itemId}/reviews; PATCH /reviews/{id}; DELETE /reviews/{id}; POST /admin/reviews/{id}/moderate. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Review `{id,productId,authorSummary,rating,title,body,media,status,createdAt}`. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Rating 1–5, body/title limits, purchase eligibility, one review per item, prohibited-content screening, media ownership. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Create/update/delete/moderate idempotent where retried; If-Match for edits; lists cursor-paginated and sortable by helpfulness/date. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
State: pending_moderation -> published/rejected; edited review may re-enter moderation. Events: ReviewSubmitted, ReviewPublished, ReviewRejected. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
PII and abuse controls, spam/rate limits, sanitize rendering, moderation audit. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
