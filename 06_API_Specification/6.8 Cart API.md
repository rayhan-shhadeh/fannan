# 6.8 Cart API

## Scope
The Cart API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/cart`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Authenticated customer; guest cart only if product policy permits.

**Authorization:** Customer owns their cart; no cross-user access. Server rechecks price, stock, eligibility at mutation and checkout. All access checks are server-side and use the identity/role model in unavailable Section 5.5; do not infer role or ownership from request fields.

## Endpoint inventory
GET /cart; POST /cart/items; PATCH /cart/items/{itemId}; DELETE /cart/items/{itemId}; DELETE /cart; POST /cart/validate; POST /cart/merge. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Cart `{id,items:[{itemId,productId,quantity,unitPrice}],subtotal,discounts,total,currency,version}`. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Quantity positive and bounded, product purchasable, currency consistency, duplicate line merge, offer eligibility. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Item mutations use Idempotency-Key; If-Match on cart version; validation may return warnings without mutation. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
CartItemAdded, CartItemChanged, CartAbandoned; inventory is reserved only by checkout policy. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
Do not trust client totals; prevent price/quantity races and IDOR; avoid storing payment credentials. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
