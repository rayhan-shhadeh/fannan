# 6.11 Shipping API

## Scope
The Shipping API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/shipping`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Customer; fulfillment staff/artist; carrier webhook; admin.

**Authorization:** Customer manages address before order lock; fulfillment actor manages shipment only for owned/assigned order; carrier callbacks are signed. All access checks are server-side and use the identity/role model in unavailable Section 5.5; do not infer role or ownership from request fields.

## Endpoint inventory
GET /shipping/methods; POST /shipping/quotes; GET /orders/{id}/shipments; POST /orders/{id}/shipments; POST /shipments/{id}/label; POST /shipping/webhooks/{carrier}; GET /shipments/{id}/tracking. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Shipment `{id,orderId,status,carrier,service,trackingNumberMasked,addressSummary,events}`; quote includes amount/currency/estimated windows. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Address and package validation, supported country/service, order state, carrier event schema and signature. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Shipment creation/label generation/webhook ingestion idempotent; cursor tracking events. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
State: pending ? label_created ? in_transit ? delivered; exception/returned are terminal branches. Events: ShipmentCreated, ShipmentDispatched, ShipmentDelivered, ShipmentException. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
PII minimization, tracking access control, signed callbacks, protect label URLs. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
