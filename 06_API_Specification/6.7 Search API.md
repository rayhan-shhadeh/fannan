# 6.7 Search API

## Scope
The Search API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/search`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Public visitor; authenticated user for personalized results; admin for synonym controls.

**Authorization:** Search only indexes visible/published entities. Personalization is opt-in and must not change authorization. Admin manages synonyms/boosts with audit. All access checks are server-side and use the identity/role model in the missing Section 05 authentication/authorization source; do not infer role or ownership from request fields.

## Endpoint inventory
GET /search; GET /search/suggestions; GET /search/filters; GET /admin/search/synonyms; POST/PATCH/DELETE /admin/search/synonyms/{id}. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Result `{type,id,title,thumbnail,artist,price,score,highlights}`; query example `/search-q=blue+ceramic&type=product&categoryId=cat_1&limit=20`. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Query length/encoding, allow-listed types/filters/sorts, min/max price and category validation, safe highlighting. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Read-only; cacheable with visibility-aware keys. Admin synonym writes use keys and If-Match. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
SearchIndexed, SearchVisibilityChanged, SearchSynonymChanged. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
Rate limit by IP and actor; escape highlights; never expose hidden products or raw index queries. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
