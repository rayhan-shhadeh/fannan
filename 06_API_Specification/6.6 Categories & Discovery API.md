# 6.6 Categories & Discovery API

## Scope
The Categories & Discovery API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/categories`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Public visitor; admin taxonomy manager.

**Authorization:** Public users read active categories and curated discovery; only catalog admins change taxonomy or featured sets. All access checks are server-side and use the identity/role model in unavailable Section 5.5; do not infer role or ownership from request fields.

## Endpoint inventory
GET /categories; GET /categories/{id}; GET /discovery/featured; GET /discovery/trending; GET /discovery/collections/{slug}; POST/PATCH/DELETE /admin/categories/{id}. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Category `{id,name,slug,parentId,childrenCount}`; discovery returns cards with product/artist summary and pagination. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Slug/name uniqueness, no cycles, depth limit, active visibility, safe collection query constraints. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Admin writes are idempotent and audited; reads use cursor pagination and cache validators. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
CategoryCreated, CategoryChanged, CategoryArchived, CollectionPublished. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
Public responses omit drafts; prevent unbounded tree traversal and injection in curated query definitions. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
