# 6.12 Offers & Negotiation API

## Scope
The Offers & Negotiation API is the HTTP contract for the corresponding FANNAN MVP module. It follows [6.0 API Architecture & Standards](6.0%20API%20Architecture%20%26%20Standards.md) and [6.1 API Conventions](6.1%20API%20Conventions.md). Base path: `/offers`. This is specification documentation, not implementation code.

## Actors, authentication, and authorization
**Actors:** Authenticated customer and owning artist; admin moderation.

**Authorization:** Only buyer and product artist can read/respond to an offer; offer visibility never follows a client-supplied user ID. All access checks are server-side and use the identity/role model in unavailable Section 5.5; do not infer role or ownership from request fields.

## Endpoint inventory
POST /products/{id}/offers; GET /offers; GET /offers/{id}; POST /offers/{id}/counter; POST /offers/{id}/accept; POST /offers/{id}/reject; POST /offers/{id}/expire. All endpoints return the common error envelope and `X-Request-Id`. Public endpoints still apply visibility, moderation, and rate-limit rules in [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md).

## Representations and examples
Offer `{id,productId,buyerId,artistId,amount,currency,status,expiresAt,version}`. Responses omit secrets and fields outside the actor's scope. Money, timestamps, IDs, pagination, and errors follow [6.1](6.1%20API%20Conventions.md).

## Validation and business rules
Amount/currency, product availability, expiry, participant identity, maximum rounds, one active offer policy, no offer below configured floor. Validation occurs before side effects; authorization occurs before revealing whether a protected resource exists (use indistinguishable 404 where required).

## Idempotency, pagination, and concurrency
Create/counter/respond require keys and If-Match; expired offers return conflict. Lists use cursor pagination (`limit`, `cursor`) and allow-listed filters/sorts. Mutations use `If-Match` where a version is returned. Retries and conflict handling follow [6.0](6.0%20API%20Architecture%20%26%20Standards.md).

## State transitions and events
State: proposed ? countered ? accepted/rejected/expired/withdrawn; acceptance may create a checkout price lock, never silently alter catalog price. Events: OfferCreated, OfferCountered, OfferAccepted, OfferRejected, OfferExpired. Event payloads include `eventId`, `type`, `occurredAt`, `aggregateId`, `actorId` (when safe), and schema version. Events are emitted after commit, delivered at least once, and must not contain secrets.

## Security and privacy
Private negotiation data, abuse throttling, authorization on both parties, audit decisions. Apply centralized transport, input, logging, abuse, and rate-limit rules from [6.17](6.17%20API%20Security%20%26%20Rate%20Limiting.md), without defining a second authentication model.
